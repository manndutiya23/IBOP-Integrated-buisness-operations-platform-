# Integrated Business Operations Platform (IBOP)

This repository contains a student final-year project: a small integrated business operations platform with a React frontend (Vite + Tailwind) and an Express + MongoDB backend. The app supports role-based access control (RBAC), basic CRUD for products, sales, purchases, invoices, expenses, and employee authentication.
**Repository layout**
- `backend/` — Express API (controllers, models, routes, DB connection).
- `src/` — React frontend (pages, components, context providers, utilities).

## Features
- Role-based authentication (JWT) and protected routes.
- Employee management with auto-generated default password (demo use).
- Product, Purchase, Sale, Invoice, and Expense management APIs and UI.

## Tech stack
- Frontend: React (Vite), Tailwind CSS, React Router, Recharts.
- Backend: Node.js, Express, Mongoose (MongoDB), JWT, bcrypt.
- Utilities: Axios for API calls, jsPDF for PDF export.

## Prerequisites
- Node.js (16+ recommended)
- npm or yarn
- MongoDB instance (local or cloud)

## Environment
Create a `.env` file in `backend/` (or copy `.env.example`) and set:

- `MONGO_URI` — MongoDB connection string
- `JWT_SECRET` — secret key for JWT tokens

Example: see [backend/.env.example](backend/.env.example)

## Setup and run (development)

1. Install dependencies for frontend and backend:

```bash
# from repository root
npm install
cd backend && npm install
```

2. Start backend (in `backend/`):

```bash
# create .env with MONGO_URI and JWT_SECRET, then:
node server.js
```

3. Start frontend (from repository root):

```bash
npm run dev
```

Notes:
- The frontend expects the API base URL `http://localhost:5000/api` by default (see `src/utils/axiosConfig.js`). If your backend runs on a different host/port, update that file or set up a proxy.
- `backend/package.json` currently has no `start` script; using `node server.js` is the simplest way to run the API.

## Usage
- Register or use an existing employee via the API (or add a seed user) and login from the frontend `/login` page.
- The app uses roles (`Admin`, `Management`, `Sales`, `Finance`, `HR`, `Supply Chain`) to control access to modules and routes.

## Development notes & recommendations
- Add `start`/`dev` scripts to `backend/package.json` (e.g., `nodemon server.js`) for easier development.
- Add request validation (e.g., `express-validator`) and centralized error handling middleware.
- Add seed data or a small `scripts/seed.js` to create an initial Admin user to simplify grading/testing.
- Add basic tests for auth and core endpoints.
- Consider moving sensitive defaults (like autogenerated passwords) to a safer setup for production.
